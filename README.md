# 胎动 JiQian

孕期记录 iOS App —— 胎动计数、宫缩计时、体重记录、就诊摘要，**快捷指令优先**。

原生 SwiftUI + SwiftData + **App Intents / App Shortcuts**。装好之后，Siri、操作按钮、控制中心、锁屏都能一句话记一次胎动或一次宫缩。

> 这不是医疗设备。全部提示都是「建议联系产科机构」，不做任何诊断判断。

---

## 为什么是「云端编译」

编译 iOS App 必须有 macOS + Xcode。你的机器没有 Mac，所以这个仓库自带一条 GitHub Actions 流水线：**推到 GitHub 上，云端 macOS 机器自动编译，产出可以直接拿去自签名的 `.ipa`。**

整条链路不需要你本地装任何东西。

---

## 三步拿到可安装的 IPA

### 1. 推到你的 GitHub

仓库已经在本地提交好（分支 `main`）。在仓库目录执行：

```bash
git remote add origin https://github.com/<你的用户名>/<仓库名>.git
git push -u origin main
```

### 2. 等云端编译

推送后自动触发 `Build unsigned IPA`：

- 进入仓库 → **Actions** → 选 `Build unsigned IPA`
- 等 3～5 分钟，变绿
- 点进这次运行 → 页面底部 **Artifacts** → 下载 `JiQian-unsigned-ipa`
- 解压得到 `JiQian-unsigned.ipa`

也可以手动触发：Actions → Build unsigned IPA → Run workflow。

### 3. 用你的证书自签名

这个 IPA 是**未签名**的，正是给自签名工具用的。任选一种：

| 工具 | 平台 | 说明 |
|---|---|---|
| **Sideloadly** | Win / Mac | 最直接，支持自备 `.p12` + `.mobileprovision` |
| **AltStore / SideStore** | Win / Mac | 用 Apple ID 签名，免费账号 7 天需续签 |
| **ESign / 爱思助手** | iOS / Win | 手机上直接签名安装 |

**关键一点：Bundle ID 必须和你的描述文件匹配。** 打开 `project.yml`，改这一行再重新构建：

```yaml
PRODUCT_BUNDLE_IDENTIFIER: com.jiqian.app   # 改成你证书里注册过的 App ID
```

Sideloadly 里也可以直接勾选修改 Bundle ID，两者选一个即可。

装好后如果提示「不受信任的开发者」：设置 → 通用 → VPN 与设备管理 → 信任你的证书。iOS 16 以上还需要：设置 → 隐私与安全性 → **开发者模式** → 打开并重启。

## 装好后怎么用快捷指令

**不用你手动搭快捷指令。** App 首次启动时就把动作注册进系统了，`App Shortcuts` 会自动出现在「快捷指令」App、Siri、聚焦搜索里。

### 五个动作

| 动作 | Siri 短语 | 行为 |
|---|---|---|
| 记一次胎动 | 记一次胎动 | 立刻写一条，本轮第 N 次，不打开界面 |
| 开始数胎动 | 开始数胎动 | 新建一轮计数会话（会打开 App） |
| 宫缩开始 / 结束 | 记录宫缩 | 没在计时就开始，在计时就结束并保存 |
| 结束宫缩计时 | 结束宫缩 | 只做结束，绝不误开新计时 |
| 就诊摘要 | 打开就诊摘要 | 直接跳到摘要页 |

### 三个入口

- **Siri**：「嘿 Siri，记一次胎动」
- **操作按钮**（iPhone 15 及以后）：设置 → 操作按钮 → 快捷指令 → 选「记一次胎动」
- **控制中心 / 锁屏**：控制中心 → 添加控制 → 快捷指令；锁屏小组件同理

如果 Siri 一开始不认识，**对着手机说一次短语**即可，系统会把它记进建议。

> 设计上刻意只留 5 个动作：宫缩天然是「开 / 关」两态，一个动作就够；胎动则是「单次」和「开始一轮」两个语义，不能合并。

## 锁屏 / 桌面组件（v4.9，双端）

### iOS：Widget Extension（`JiQianWidgets`）

三个组件，各自独立添加：

| 组件 | 支持的尺寸 | 点一下会发生什么 |
|---|---|---|
| 胎动 · 锁屏开关 | 锁屏圆形 / 长条 / 单行文字 | 立刻记一次胎动 |
| 宫缩 · 锁屏开关 | 锁屏圆形 / 长条 / 单行文字 | 没在计时就开始；正在计时就结束并保存 |
| 胎动 / 宫缩 快捷开关 | 桌面小号 / 中号 | 两个并排的开关，分别触发上面的动作 |

- 添加路径：锁屏长按 → 自定义 → 锁定屏幕 → 添加小组件 → 搜「胎动」；桌面长按 → 左上角「+」→ 搜「胎动」。设置页也有同样三步指引。
- **实现方式**：组件用 `Link` 打开 `jiqian://quick-kick` / `jiqian://quick-contraction`，App 在 `onOpenURL` 里立刻落库（走与界面按钮完全相同的记录器），底部弹出「已记下第 N 次胎动」「已保存本次宫缩 1:12」之类的结果提示。因此组件不需要 App Group、也不需要共享数据库，自签名安装不会因为权限配置失败。
- 只读端（查看模式）点组件同样会被拦截，提示去申请编辑权限。
- 为什么组件上不显示今日次数：那需要 App（主 App 容器）与扩展（Extension 容器）共享数据，也就是 App Group 能力——免费 Apple ID 签名不支持 App Group。等有付费开发者账号时可以补上实时数字。

### 安卓：RemoteViews 桌面组件（`com.jiqian.app.widget`）

安卓从 5.0 起系统层面取消了锁屏组件，所以只做桌面组件——但因为是同一进程、同一份 SharedPreferences，**组件上的数字是真实的、点击就地生效，不用打开 App**：

| 组件 | 尺寸 | 显示 | 点一下 |
|---|---|---|---|
| 胎动 · 记一下 | 2×2 | 今日次数 / 上次时间 / 本轮次数 | 记一次胎动 |
| 宫缩 · 计时开关 | 2×2 | 就绪或正在走秒的计时器 | 开始 / 结束并保存 |
| 胎动 / 宫缩 快捷开关 | 4×2 | 今日与本轮次数 + 上次胎动时间 | 两个开关并排 |

- 添加路径：桌面长按空白处 → 小组件 → 搜「胎动记录」。设置页也有说明。
- 计时用 `Chronometer` 直接挂在组件上走秒；宫缩的「正在计时」状态存在 SharedPreferences（`ctn_running`），App 与组件共用，App 被杀掉再打开也能接着走。
- 每次记录后组件原地刷新（`Widgets.refresh`），并走与 App 相同的记录入口（`Store.addKick` / `addContraction`），因此同步、墓碑、只读端拦截全部同样生效。
- 零新增依赖：只用系统 `RemoteViews`，不引入 Glance，升级时不会带进 Compose 版本冲突。

## 配对同步（v4.8，双端）

「设置 → ☁️ 配对同步」。一台手机创建 6 位配对码，另一台输入同一个码即绑定；之后双方联网就自动双向同步全部胎动与宫缩记录。

- **权限分级（v4.7 新增）**：创建配对码的手机自动成为可编辑端；加入的手机默认进入**查看模式**——只能看同步来的记录，App 内所有记录入口（胎动按钮、宫缩计时、撤销、清空、快捷指令）都被拦截，云端推送也只允许权限申请变动、不允许数据写入。想修改数据时在「配对同步」页点「申请编辑权限」，创建端会看到待审批列表，点「同意」后约 6 秒内对方获得写权限。权限表（owner / writers / 申请列表）存在加密快照内随数据同步，合并规则双端一致且确定性收敛。

- **申请提醒（v4.8 新增）**：加入端发出申请后，可编辑端会收到三重提示——系统本地通知（前台也弹横幅，点通知直接跳到审批页）、首页顶部常驻「设备 XXXX 申请编辑权限 · 点此审批」横幅、设置页「配对同步」行的红色「N 待审批」角标。同一台设备只提醒一次；被忽略后再次申请会重新提醒。同步与点按同时发生时会保留本机最新的权限改动并自动补推，不会把申请吞掉。

- **撤销申请 / 忽略申请（v5.0 修复）**：以前「点按撤销申请」看着有提示却撤不掉——审查后发现是合并规则的问题：权限表按「并集」合并，本机删掉的那条申请会被对端那条并回来，而且这一轮还会因为「合并结果等于本机旧值」被判定为不需要推送。现在权限表新增 `rv`（撤销记录：设备 + 撤销时刻），合并时「撤销」压住更早的申请」，撤销时刻取「对应申请时间 + 1ms」抵消两端时钟差；待推送判断也改成「本机权限表与云端是否一致」。同理修复了创建端点「忽略」后申请又冒回来的问题。重新申请不受影响（新申请时间一定比撤销记录新）。

- **预产期同步（v5.1 新增）**：预产期原来只存在本机，配对后两端各算各的孕周。现在快照里加了 `st`（`edd` = 预产期当天 0 点毫秒、`t` = 最后修改时刻），合并取 `t` 大的一条（`t` 相同再比 `edd`），改动后约 6 秒内同步到对方的「设置 → 孕周与目标」；比本机记录旧的值不会覆盖本机，刚改好不会被旧值弹回去。查看模式（只读端）不能改预产期，需先申请编辑权限。安卓这版也补上了预产期入口与「当前孕周」显示，摘要里同样带孕周。

- **共享设置同步（v5.2 扩大范围）**：`st` 从「只有预产期」扩成整段共享设置——预产期、每轮时长、计数窗口、高风险因素勾选、产科联系方式（机构名称 / 联系电话），全部随配对同步，改动后约 6 秒到对方。合并仍是 LWW（t 大者胜），t 相同按字段字典序决胜，双端规则逐字一致、必然收敛；落地只接受「不比自己旧」的值。点击提示音 / 音量 / 震动 / 宫缩按住方式属于个人偏好，仍各存各的。安卓不展示的设置（计数窗口、高风险因素、产科联系方式）也会原样透传，不会在安卓推送时被抹掉。另外查看模式（只读端）现在没有「清空记录」入口：iOS 整行隐藏，安卓按钮锁死——B 手机同步来的记录不能在 B 端清空。

- **实时性**：本机改动约 2 秒防抖后上传；其他手机开着 App 时每 6 秒轮询一次云端 `rev` 版本号（只查一列），发现变化才拉取；切回 App 立即同步，退到后台停止轮询并抢推未上传改动。
- **端到端加密**：配对码 + 每次配对的随机盐 → PBKDF2-HMAC-SHA256（10 万轮）派生密钥 → AES-256-GCM 加密整份快照后才上传。云端 `payload` 只存 `{v,salt,iv,ct}` 密文信封，数据库泄露也读不出任何记录。iOS（CryptoKit/CommonCrypto）与安卓（javax.crypto）算法、信封格式逐字节一致。
- **合并规则**（双端一致）：记录按 id / 时间锚点并集，双方新增都保留；同一处冲突做字段级融合（结束时间取较晚非空值、备注取非空值、可疑标记取或）。
- **删除同步**：「撤销上一次」「清空胎动/宫缩」写单条墓碑（180 天过期、2000 条上限）；iOS「清空全部记录」写清空时间戳，所有设备锚点早于它的记录一并删除。
- **多机**：一个配对码可加任意多部手机（准爸爸、长辈都能加）；「解除配对」只停止同步，本机与云端记录都保留，重输配对码可再次加入。
- **云端**：按配对码索引的单行快照（WorkBuddy 托管 PostgreSQL，REST 匿名读写经 publishableKey 鉴权），复用萌宝成长已在线的同款后端与 `mengbao_sync` 表——胎动 payload 同为密文信封，且两端建码查重共用同表天然避免撞码。若要换独立环境，只改 `CloudCfg` 一处。

### 设备管理（v5.3，双端）

创建配对码的 A 手机（owner）在「配对同步」页多出一张**设备管理卡**，对每台加入的 B 设备：

| 能力 | 做什么 | B 端会发生什么 |
| --- | --- | --- |
| 单独同步某类数据 | 三个开关：胎动 / 宫缩 / 设置（预产期、每轮时长、计数窗口、高风险因素、产科联系方式） | 被关掉的类别在 B 端不再落地、已有的会被清掉；打开后约 6 秒内恢复同步 |
| 强制解绑 | 移出 writers 并写解绑记录（`acl.ub`，只增不减、180 天过期） | B 约 6 秒内自动解除配对并弹通知；**B 本机记录保留**；被解绑的设备无法用原配对码再加入 |
| 清除数据 | 下发清除命令（`acl.wp`，隐含解绑） | B 联网后**清空本机全部记录**并自动解除配对、弹通知；A 与云端记录不受影响 |

- 全部命令随端到端加密快照同步，合并规则双端逐字一致：`ub`/`wp` 按「id 并集取最大 t」只增不减（被解绑的设备无法靠并集混回 writers），`sm` 掩码按设备 LWW（t 大者胜）。
- B 端命中 `ub`/`wp` 时**就地处理并跳过本轮推送**——清空后的 B 绝不会把空数据盖回云端。
- 通知与权限申请提醒一样是本地通知：B 的 App 在前台时约 6 秒内弹出；被系统挂起则等它回到前台再处理。

## 体重记录（v5.4，双端）

iOS 首页多一张「体重」卡片（点进去是独立页）；安卓底部栏多一个「体重」标签。这一页只记两件事：**什么时候称、多少公斤**，不出现任何增重评价、范围建议或健康判断。

- **录入**：数字键盘填公斤数，另有 −0.5 / −0.1 / +0.1 / +0.5 微调；可回填过去某一天（钟点沿用当前时间）。范围限制 30–200 kg，防手滑打成 6.2 或 620。
- **曲线**：最近 30 次自绘折线（iOS 用 `Path`、安卓用 `Canvas`，不引第三方图表库），下方标注首末日期与数值；列表按时间倒序，显示与上一条的差值。
- **同步**：快照新增 `we` 字段（`id` / `at` 称重毫秒 / `kg`），删除写 `we@<毫秒>` 墓碑，与胎动共用同一套合并、180 天墓碑过期规则；`sm` 掩码新增 `w` 位，A 端在设备管理卡里可以单独关掉「把体重同步给这台手机」。
- **向后兼容**：`we` 是**可选字段**——旧版客户端发来的快照没有它时跳过处理，绝不把本机体重当成「对方为空」清掉；旧掩码没有 `w` 位时按「同步」处理。
- **摘要**：就诊摘要新增【体重】段，写最近一次的时间与公斤、时段内记录次数与前后差；iOS「清空全部记录」会一并清掉体重，确认文案里写明了条数。
- **查看模式**：只读端的体重入口与胎动 / 宫缩一致被锁死，需要先在「配对同步」申请编辑权限。

## 关键设计取舍

- **原始事件与结论分离**：每条记录只存时间、来源、时区；「是否需要联系」在读取时按当前规则重算，历史记录不会被未来的规则改写。
- **不静默丢数据**：宫缩的开始与结束都是立即落库。App 被杀、来电打断、锁屏，重开仍能恢复。
- **1.2 秒去重**：同来源、同 1.2 秒内的重复点按视为误触，不重复计数。
- **本地优先**：无账号、无广告。默认不配对时零网络流量，数据只在设备内；配对同步开启后也只上传端到端加密的密文。
- **文案红线**：所有 Siri 返回只讲「已记录 / 已保存 / 请确认」，绝不输出「正常 / 异常 / 该不该去医院」。

宫缩提示口径（与网页版一致）：近 1 小时有效收缩 ≥ 6 次、平均持续 ≥ 45 秒、平均间隔 ≤ 10 分钟。存在高风险因素（未足月、多胎、既往早产/急产、计划剖宫产等）时，未达阈值也会更早提示。

## 已知限制

- 没有 Live Activity：灵动岛/锁屏实时跳动计时还没做（v4.9 已有锁屏与桌面组件，但组件上不显示实时秒数）。
- 配对同步需要联网；不配对时一切只存本机，行为与 v4.5 完全一致。
- 编辑权限申请的提醒不是服务器推送：只读端发出申请后，可编辑端的 App 在前台时约 6 秒内弹通知；若 App 已在后台被系统挂起，则要等它回到前台（或重新打开）时才会提醒——云端数据仍在，不会丢。真正的后台实时推送需要 APNs / FCM 服务端，超出当前无账号、纯本地架构的范围。
- 没有 HealthKit 写入。
- 免费 Apple ID 签名 7 天过期，需用工具续签；付费开发者证书则为 1 年。
